# herdr-toolkit

Personal customizations for the [Herdr](https://herdr.dev) desktop app.

## Set it up on a machine

This repo is laid out like a Herdr home (`layouts/VNH.json`, the `mods/` it uses) with a `RECIPE.md`, the way Herdr's gallery expects, so an agent can build the whole UI from it.

**With an agent** (Herdr's own way), in Herdr or any agent that can read your files:

```
Read ~/.config/herdr-app/AGENTS.md, then add this layout: https://github.com/vunamhung/herdr-toolkit/tree/main
```

The agent reads `RECIPE.md` and the files, tells you what the mods reach (network, programs, files outside their folder) and what `install.sh` changes in `~/.claude`, `~/.codex` and `~/.gemini`, then installs.

**By hand:**

1. Start Herdr once (it writes its home), and have node 20+ for herdr-chat's host.
2. `git clone` this repo and run `./install.sh --layout` (add `--orca`, `--karabiner`, `--gestures` as you like). It installs everything the layout uses from this repo alone: our mods, the third-party mods it builds on (`better-changes`, `filetree`, `cloudflare-deploys`, `insights`, `walkthrough`, `portal`, `run`, already modified), herdr-chat with its host (`vendor/herdr-chat`), and `jq` (`bin/`, official builds, so none is needed on the machine). It backs up what it changes and can be run again.
3. Codex only: run `/hooks` in Codex once and trust the Herdr status hook.

**Same UI as the author's, and what isn't:** the layout, mods, keys, theme, status bar and look settings (size, line height) are all in the repo. The font isn't (the author's is commercial): pick one in Settings > Look. **Windows is not tested**: Herdr runs there, but most mods call `sh`, `osascript` or `open`, herdr-chat's installer is a shell script that upstream supports on macOS only, and `install.sh` needs bash (Git Bash). Expect part of it to work, and the status scripts and `jq.exe` are there for it; use macOS for the exact result.

`preview.png` is a screenshot of the author's real window, so the space names, task titles and paths in it are the author's own.

## Install

```sh
./install.sh            # mods + status line script
./install.sh --layout   # also the layout + its keys, and switch Herdr to it
./install.sh --karabiner  # also the Cmd+` -> Herdr Karabiner rule (combine flags freely)
```

Existing files are backed up as `<file>.bak-<timestamp>`.

The layout also places mods that `install.sh` installs from this repo (third-party ones are under `mods/` with their own `LICENSE`; `chat`, `new-chat`, `chat-menu`, `chat-agents` come from `vendor/herdr-chat`): `chat-agents`, `new-chat`, `insights` (its toolbar button sits after the tab bar), `filetree` (the Files panel, modified here: it adds a ⊙ / ⊘ button and `i` to show or hide git-ignored files and folders, and makes rows draggable into a terminal or an agent input as `@path` like `vnh-files`; a Markdown file opens rendered in `vnh-markdown` from the eye right after its name (brightens under the pointer) or in its preview, or with Space, and Esc or Space there closes the tab and gives the keyboard back to the tree), `walkthrough` ([dmazlum/herdr-walkthrough](https://github.com/dmazlum/herdr-walkthrough), `⌘⇧K`: a diff (uncommitted, staged, branch, commit, PR, last turn) explained step by step by `claude -p` with no tools; its Last turn hooks are in `claude/walkthrough-hooks.json`, merge them into `~/.claude/settings.json` `hooks`), `portal` ([CodeyPacker/herdr-mods](https://github.com/CodeyPacker/herdr-mods/tree/main/portal), `ctrl-shift-u`: every local TCP/UDP port by owning process, favorites, open in the browser, end a process after a confirm; modified here for macOS 14, whose `netstat -anv` has no `name:pid` column, which the stock parser needs), `run` ([CodeyPacker/herdr-mods](https://github.com/CodeyPacker/herdr-mods/tree/main/run), `ctrl-shift-r` opens it, `ctrl-shift-q` closes a popup; runs the processes a repo declares in `herdr.procs.json` as background terminals, with single-key start / stop / restart / peek), `cloudflare-deploys` ([SaifHarding/herdr-cloudflare](https://github.com/SaifHarding/herdr-cloudflare), the cloud icon at the right of the sidebar's branch row (the `brand-row`); read-only. With wrangler instead of an API token every check starts one node process per project, so set `CF_POLL_SECONDS=300` in `~/.config/cloudflare-deploys/.env`, and `CF_WRANGLER` to a global wrangler if a repo's `node_modules/.bin/wrangler` is broken), `better-changes` ([munza/herdr-mods](https://github.com/munza/herdr-mods/tree/main/better-changes), the Changes panel; set its `mod.json` `place` to `"none"`, or Herdr docks a second copy around the layout and breaks the titlebar). A group draws its first 150 files and adds 300 more per click on "Show more" (a repo with hundreds of changed files made one render so long that Herdr interrupted it and the panel showed "This view could not be re-rendered … interrupted"). Each file row has a checkbox instead of `+` / `−`: ticked is staged, a click stages or unstages. ## Restore defaults

- In-terminal Claude status line: delete the `exit 0` line under "publish model + limits" in `~/.claude/statusline.sh`. The full two-line status line is still below it.
- Herdr's stock status bar: in the layout, change `"mod": "claude-limits-status"` back to `"mod": "workspace-status"`.
- Herdr's stock layout: `herdr-app do layout.switch '{"name":"main"}'`, or press `ctrl-alt-shift-escape`.

## Notes

- Several Claude Code sessions can run at once. The model and context % shown are from the session that refreshed last; the 5h and 7d limits are account-wide.
- Rate limits arrive only after a session's first API response; until then the previous values are kept.

- The VNH mods share the last focused terminal folder per space (`vnh.lastCwd`, kept by `vnh-tabs`, and by `vnh-files` when it is placed), so mod panes such as the Markdown viewer don't switch the Files panel, run bar, `⌘↩` popup or status bar to the space's starting folder (which can be another project).
- `claude/filetree-hooks.json`: the Claude Code hooks for filetree's activity bridge (reads purple, writes orange, commits green, the Recent tab). Merge its four entries into `~/.claude/settings.json` `hooks` (after any you have); they run `~/.bun/bin/bun` on `mods/filetree/bridge.ts`, print nothing, always exit 0, and append to `~/.local/state/herdr-filetree/activity.jsonl`.
- `overlays/`: files that live inside a third-party mod or Herdr's own app frame, so a mod or Herdr update overwrites them — `install.sh` copies each one into `~/.config/herdr-app/` (backing up what was there), and you re-run install after such an update. Today it carries `chat`, `chat-agents` and the **Settings → Mods** tab (walkthrough's Vietnamese and anchored dropdown are in `mods/walkthrough` itself); the **Settings → Mods** tab (`overlays/frame/settings/main.js` + `blocks.svg`) is a read-only list of every mod under `mods/` with its version, source (Herdr / VNH / 3rd-party) and whether the active layout places it — it replaces `better-config`'s mod list, which is why that mod and its `⌘⌥,` binding are gone.
- **Status bar model and limits** (`claude-limits-status`): plain text, no menu. It shows the agent in front of you, by the name that agent uses — `Opus 4.8 high`, `GPT-5.6-Terra high`, `Gemini 3.8 Flash high` (the effort is always dimmed and has no brackets: Antigravity's `(High)` is split off the name) — and that agent's own `5h` / `7d` usage and context, so switching between Claude Code, Codex and Antigravity (agy) switches the bar. Each agent writes `~/.cache/herdr-status/<terminal>.json` for its terminal and the bar reads the file of the focused terminal: **Claude Code** from its status line command; **agy** from its `statusLine` command (`status/agy.sh`: `model`, `context_window`, and the `quota` buckets: `gemini-*` for Gemini models, `3p-*` for the third-party ones; nothing else of its payload — it holds the account e-mail — is read or stored); **Codex** from a lifecycle hook (`status/codex.sh`: the model from the hook payload, its display name from `~/.codex/models_cache.json`, and effort, context and the primary / secondary usage windows from the session's rollout file). Codex holds a new hook until you trust it: run `/hooks` in Codex once. **Titles:** agy sets no terminal title (Herdr would show its command line, `agy --dangerously-…`), so `status/agy.sh` also stores the conversation's first prompt (from agy's `history.jsonl`, by the `conversation_id` in its status line payload) as `title` in the same file; `vnh-tabs` publishes those in shared `vnh.titles` and the tab bar and the Agents list show them. An agy session gets its title the next time its status line refreshes (when you use it). A terminal whose agent hasn't written its file yet, or whose file is from another agent that ran there before, shows `…` instead of someone else's model; a shell or a mod pane keeps the last agent. **Codex has not been run against a real session** (it was not logged in): the hook and its parsing were tested on a rollout built from the format, so check the first real session. **Chats** (`herdr-chat`, which runs the agent headless, so no hook or status line runs): with `overlays/mods/chat/main.js` (installed by `install.sh`) the chat in front of you publishes its provider, model, effort and context under its tab id in shared `vnh.chat`, and the bar shows them (Claude chats take Claude's 5h / 7d). Run `install.sh` again after herdr-chat updates.
- `claude/model-switch-hook.json`: an optional `PreModelSwitch` hook returning `permissionDecision: "allow"`, which makes Claude Code skip the confirmation it shows while the prompt cache is warm when you run `/model` by hand. Merge it into `~/.claude/settings.json` `hooks` only if you want that; a running agent picks it up live, and dropping the file keeps the confirmation.
- The Cloudflare icon (`mods/cloudflare-deploys`, modified) in the sidebar's brand row drew its own bottom border, a line under the icon alone that the branch button beside it doesn't have; the copy here removes it, so the brand row has no line under it at all.
- Performance (audited): third-party panels in the side panel stop reading while hidden (the filetree changes) and catch up when shown; filetree ignores `.git` noise such as fsmonitor cookies, which made it run `git status` at every other tool's pace in repos with `core.fsmonitor=true`; the status bar's git reads pass `-c core.fsmonitor=false`; `cloudflare-deploys` here runs at most 3 wrangler fetches at once (each is a ~260 MB node process). The tab bar and pane headers draw no working spinner: the sidebar's Agents list is the one place that shows it, as a slowly breathing dot (`overlays/mods/chat-agents`).
- The walkthrough Last turn hook adds about 0.7 s before a prompt is sent in a large repo (it snapshots the working tree), and 0.3 s when a turn ends.
- `⌘\` (`vnh-tabs.insights`) opens / closes the Insights dashboard (the icon at the right end of the tab bar does the same; Esc closes it).
- `vnh-tabs.git-push` (the Git menu's Push, and the pinch-apart gesture; no key) pushes with no dialog: the current branch of the repo you work in (the active space's last terminal folder) to its upstream, else to `origin` (or the first remote) with `--set-upstream`, then `git push <remote> --tags`; never forced, `GIT_TERMINAL_PROMPT=0` so a missing login fails instead of hanging; the result is a toast.
- Trackpad pinch anywhere in Herdr, terminals included, runs git on the work folder's repo: pinching the fingers together runs `git pull --ff-only` (`vnh-tabs.git-pull`), spreading them apart pushes the branch and its tags as `⌘\` does (the plist's `HERDR_PINCH_TOGETHER` / `HERDR_PINCH_APART` and `HERDR_PINCH_IN` / `HERDR_PINCH_OUT` change the commands and thresholds without a rebuild; a rebuild needs Accessibility granted again). Mods only see pinches over what they draw, so `gestures/HerdrPinch.swift` (built into `~/Applications/HerdrPinch.app`, signed ad hoc, run by the LaunchAgent `dev.vnh.herdr-pinch`, `./install.sh --gestures`) watches magnify gestures system-wide and acts only while Herdr is frontmost: once per gesture, past a clear pinch (+0.35 / −0.3 of scale), at most every 3 s. Log: `~/Library/Logs/herdr-pinch.log`. Remove: `launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/dev.vnh.herdr-pinch.plist` and delete the plist and binary.
